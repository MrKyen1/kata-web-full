0. API BASE CONFIG
======================================================================

Backend base URL:

  http://localhost:3000/api/v1

Vite .env:

  VITE_API_BASE_URL=http://localhost:3000/api/v1

IMPORTANT:
  Nếu axios baseURL đã là http://localhost:3000/api/v1
  thì khi gọi API KHÔNG thêm /api/v1 nữa.

Correct:
  api.post("auth/login")
  api.get("centers")
  api.get("classes")
  api.get("specializations")

Wrong:
  api.post("/api/v1/auth/login")
  api.post("v1/auth/login")

1. COMMON RESPONSE FORMAT
======================================================================

Success response:

  {
    "success": true,
    "data": ...,
    "meta": ...,
    "requestId": "...",
    "timestamp": "..."
  }

Frontend chỉ dùng:

  response.data.data


Error response:

  {
    "success": false,
    "statusCode": 400,
    "errorCode": "BAD_REQUEST",
    "message": "Dữ liệu không hợp lệ",
    "fieldErrors": {
      "email": ["email must be an email"]
    },
    "path": "/api/v1/...",
    "requestId": "...",
    "timestamp": "..."
  }

Frontend cần show:
  error.response.data.message

Nếu có validate lỗi từng field:
  error.response.data.fieldErrors

2. AXIOS CLIENT CẦN LÀM
======================================================================

Tạo file ví dụ:

  src/api/axiosConfig.ts
  src/api/apiClient.ts

Axios config:

  - baseURL lấy từ import.meta.env.VITE_API_BASE_URL
  - Content-Type: application/json
  - timeout: 30000
  - tự động gắn Authorization Bearer token nếu có accessToken
  - nếu 401 thì gọi refresh token
  - nếu refresh lỗi thì clear localStorage và redirect về /login

Pseudo code:

  const api = axios.create({
    baseURL: import.meta.env.VITE_API_BASE_URL,
    timeout: 30000,
    headers: {
      "Content-Type": "application/json"
    }
  })

  api.interceptors.request.use((config) => {
    const token = localStorage.getItem("accessToken")
    if (token) {
      config.headers.Authorization = `Bearer ${token}`
    }
    return config
  })

Helper functions nên có:

  apiGet(url, params)
  apiPost(url, data)
  apiPatch(url, data)
  apiDelete(url)

Mỗi helper return trực tiếp:

  res.data.data

3. AUTH TODO
======================================================================

Routes backend:

  PATCH /auth/me

  POST /auth/login

Các route còn lại cần:

  Authorization: Bearer <accessToken>


----------------------------------------------------------------------
3.1 LOGIN
----------------------------------------------------------------------

Endpoint:

  POST /auth/login

Payload:

  {
    "identifier": "admin",
    "password": "Admin@123456"
  }

Dev account:

  identifier: admin
  password: Admin@123456

Response data:

  {
    "user": {
      "id": "...",
      "code": "admin",
      "fullName": "System Administrator",
      "phone": "...",
      "email": "...",
      "role": {
        "id": "...",
        "code": "admin",
        "name": "Administrator",
        "permissions": [
          "users.manage",
          "rbac.manage",
          "learning.manage",
          "classes.manage",
          "request-logs.read",
          "audit-logs.read"
        ]
      }
    },
    "accessToken": "...",
    "refreshToken": "..."
  }

Frontend cần làm:

  1. Tạo màn hình login.
  2. Form gồm:
       identifier
       password
  3. Submit gọi POST auth/login.
  4. Nếu thành công:
       localStorage.setItem("accessToken", accessToken)
       localStorage.setItem("refreshToken", refreshToken)
       localStorage.setItem("user", JSON.stringify(user))
  5. Lưu user vào AuthContext.
  6. Redirect về dashboard/admin page.
  7. Nếu lỗi, show message từ backend.


----------------------------------------------------------------------
3.2 GET CURRENT USER
----------------------------------------------------------------------

Endpoint:

  GET /auth/me

Frontend cần làm:

  1. Khi app reload, kiểm tra localStorage có accessToken không.
  2. Nếu có token, gọi GET auth/me.
  3. Nếu thành công, set user vào AuthContext.
  4. Nếu lỗi 401 và refresh fail, logout.
  5. Dùng user.role.permissions để kiểm tra quyền hiển thị menu/button.


----------------------------------------------------------------------
3.3 REFRESH TOKEN
----------------------------------------------------------------------

Endpoint:

  POST /auth/refresh

Payload:

  {
    "refreshToken": "<refreshToken>"
  }

Frontend cần làm trong axios interceptor:

  1. Nếu API trả 401.
  2. Lấy refreshToken từ localStorage.
  3. Gọi POST auth/refresh.
  4. Nhận accessToken và refreshToken mới.
  5. Save lại localStorage.
  6. Retry request cũ.
  7. Nếu refresh lỗi, logout.


----------------------------------------------------------------------
3.4 LOGOUT
----------------------------------------------------------------------

Endpoint:

  POST /auth/logout

Payload:

  {
    "refreshToken": "<refreshToken>"
  }

Frontend cần làm:

  1. Khi user bấm logout:
       gọi POST auth/logout với refreshToken hiện tại.
  2. Dù API thành công hay lỗi vẫn nên:
       localStorage.removeItem("accessToken")
       localStorage.removeItem("refreshToken")
       localStorage.removeItem("user")
       clear AuthContext
       redirect /login


----------------------------------------------------------------------
3.5 LOGOUT ALL
----------------------------------------------------------------------

Endpoint:

  POST /auth/logout-all

Payload:

  Không cần body.

Frontend dùng khi muốn đăng xuất tất cả phiên đăng nhập của user.

----------------------------------------------------------------------
3.7 CHANGE PASSWORD
----------------------------------------------------------------------

Endpoint:

  PATCH /auth/change-password

Payload:

  {
    "currentPassword": "old-password",
    "newPassword": "new-password"
  }

Rule:
  newPassword tối thiểu 8 ký tự.

Frontend cần làm:

  1. Form đổi mật khẩu.
  2. Validate newPassword >= 8.
  3. Gọi API.
  4. Backend sẽ logout tất cả session.
  5. Sau khi đổi thành công, clear localStorage và redirect login.

5.3 CREATE USER
----------------------------------------------------------------------

Endpoint:

  POST /users

Payload basic:

  {
    "code": "user001",
    "password": "12345678",
    "fullName": "Nguyen Van A",
    "dateOfBirth": "2000-01-01",
    "phone": "0900000000",
    "email": "a@example.com",
    "address": "Ha Noi",
    "roleId": "<roleId>",
    "avatar": "https://..."
  }

Required fields:

  code
  password
  fullName
  dateOfBirth
  phone
  roleId

Optional fields:

  email
  address
  avatar

Rule:

  password tối thiểu 8 ký tự
  email phải đúng format email
  dateOfBirth nên là YYYY-MM-DD

Nếu tạo teacher, có thể thêm:

  {
    "teacherProfile": {
      "yearsOfExperience": 2,
      "description": "English teacher",
      "classIds": ["<classId>"],
      "specializationIds": ["<specializationId>"]
    }
  }

Nếu tạo student, có thể thêm:

  {
    "studentProfile": {
      "classIds": ["<classId>"]
    }
  }

Frontend cần làm:

  1. Tạo modal/page Create User.
  2. Load roles từ GET /roles để chọn roleId.
  3. Nếu role teacher:
       show teacherProfile fields.
       load classes và specializations.
  4. Nếu role student:
       show studentProfile fields.
       load classes.
  5. Submit POST users.
  6. Thành công thì reload list.

======================================================================
11. IMPORTANT RULES FOR COPILOT
======================================================================

1. Do not add /api/v1 inside service URLs.
   baseURL already includes /api/v1.

2. Every protected request must send:
   Authorization: Bearer accessToken

3. Always read backend data from:
   response.data.data

4. Do not send extra fields.
   Backend rejects unknown fields with 400.

5. Use backend message for error display:
   error.response.data.message

6. Use fieldErrors for form validation messages when available.

7. DELETE endpoints should show confirmation before calling API.

8. After create/update/delete, reload the related list.

9. For Classes form, load Centers first to select centerId.

10. For Users form, load Roles first to select roleId.

11. For teacher user form, load Classes and Specializations.

12. For student user form, load Classes.

13. Hide menu/buttons if user does not have required permission.

14. If 401 and refresh fails:
    clear localStorage and redirect /login.

15. If 403:
    show "Bạn không có quyền truy cập".
